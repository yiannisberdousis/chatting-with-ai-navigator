# GenSTEAMers — Chatting with AI — Full Pathway Part 3

## PART 3: Building the Prototype

**Recommended duration:** 2 × 45 minutes  
**Compact route:** 60 minutes, only with a prepared starter/template and groups already marked Ready to build  
**Default route:** Option A — Scratch  
**GenAI role:** controlled implementation environment, not design generation

## Purpose

Part 3 turns the approved, tool-neutral Chatbot Logic Blueprint from Part 2 into a small, functioning prototype. Students build from the existing blueprint; they do not redesign the purpose, user, categories, responses, fallback, limitation/safety behaviour or Part 1 requirement.

The Part 3 endpoint is a saved prototype that another group can use independently in Part 4, together with the embedded Part 3 → Part 4 Test Brief.

## Core boundary

Part 3 includes implementation, technical repair, build verification, saving and handover.

Part 3 does **not** include proper peer testing, quality ratings, evidence-based Improve / Keep decisions, verification after improvement or final reflection. Those belong to Parts 4 and 5.

## Canonical student record

The four-page Prototype Build Record is completed once for any route:

1. readiness, route, roles and saving;
2. implementation-fidelity map and Session 1 save checkpoint;
3. technical build verification and repair record;
4. Part 3 → Part 4 Test Brief and readiness decision.

No separate smoke-check sheet or handover card is required.

## Normal classroom preparation

1. Confirm every group has the Part 2 blueprint and a Ready to build / Revise first decision.
2. Select one route for the class where possible.
3. Open and test the route before the lesson.
4. Decide the anonymous save/access method.
5. Prepare the paper contingency.
6. Print only the common Build Record and the selected route materials.

## Handover to Part 4

Part 4 receives:

- the saved prototype;
- how to start and access it;
- the Part 1 principle-test idea;
- the expected observable behaviour;
- the readiness decision or precise technical limitation.

The prototype plus page 4 of the Build Record are the complete handover.


## Continuity note

The Full Pathway uses the Part 3 → Part 4 Test Brief embedded in the canonical Build Record. It replaces the separate Handover Card used in the Modular pathway.

For Scratch, use the included Full Pathway `.sb3` files. The older Modular online projects use a different fallback/limitation structure and are not the Part 3 starter.
