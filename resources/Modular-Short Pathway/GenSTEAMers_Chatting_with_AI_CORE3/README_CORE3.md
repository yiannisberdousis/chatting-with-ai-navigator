# Chatting with AI — CORE 3 Release

## CORE 3: Testing, Improving and Reflecting

**Duration:** approximately 45 minutes  
**Pathway:** Modular / Short Pathway  
**Student roles:** peer tester and chatbot creator  
**Optional GenAI role:** design coach and feedback provider, only after peer evidence is recorded  
**Implementation status:** Option A fully supported; Options B and C Work in Progress / preliminary

This release package supports CORE 3 of the modular pathway. Students independently test another group’s prototype, record what the chatbot actually does, return evidence to the creators, and use that evidence to choose **Improve** or **Keep as designed**. The creators then run a verification test and complete a concise final reflection.

The protected learning cycle is:

**Peer test → Evidence → Recommendation → Creator decision → Verify → Reflect**

The aim is not to force every group to change its prototype. A **Keep as designed** decision is valid when it is supported by a specific input and observed behaviour.

## 45-minute classroom logic

1. Reconnect with the CORE 2 prototype, Handover Card and internal mini-test baseline.
2. Pair groups and explain the two mandatory peer-test missions.
3. Run the exact CORE 1 principle test and one safe Fresh User Challenge.
4. Return evidence to the creators and compare it with the CORE 2 baseline.
5. Choose **Improve** one focused feature or **Keep as designed**.
6. Verify through a same-input re-test or a confirmation test.
7. Complete the concise reflection, save and submit.

An expected-use test, GenAI support, screenshots and whole-class sharing are optional. The prototype must already be built and test-ready before the lesson begins.

## Implementation status

### Option A — Scratch

**Fully supported in this release.** The package includes the 45-minute teacher walkthrough, a screenshot-based peer-testing and revision guide, two completed decision examples, the canonical Test-Decide-Confirm Card and a short Scratch student card.

### Option B — School-approved GenAI chatbot setup

**Work in Progress / preliminary.** The student card preserves the common evidence cycle and privacy rules. A complete platform-specific implementation guide remains under development.

### Option C — Structured paper-based chatbot logic

**Work in Progress / preliminary.** The student card preserves the common testing, decision and verification cycle. A complete printable implementation pack remains under development.

Options B and C are included to show the full architecture and should not be described as fully classroom-ready.

## Minimum materials for the supported classroom implementation

Use:

- `ChattingwithAI_TeacherGuide_Modular_CORE3.docx` or the shorter `00_CORE3_Teacher_Quick_Walkthrough_45min.docx`;
- `04_CORE3_Test_Decide_Confirm_Card.docx`;
- `05_CORE2_CORE3_Handover_Card.docx`;
- `01_CORE3_Option_A_Scratch_Peer_Testing_and_Revision_Guide.docx`;
- `06_CORE3_Scratch_Test_Decide_Confirm_Card.docx`;
- the saved CORE 2 Scratch prototype; and
- the creators’ CORE 2 internal mini-test baseline (Section 9 of each group’s completed CORE 2 Student Design Worksheet — no new printable is required).

Optional:

- `03_CORE3_Completed_Revision_Decision_Examples.docx` for modelling or differentiation;
- one expected-use test, only when a group is clearly ahead of time;
- GenAI feedback after peer evidence has already been recorded; and
- screenshots, where useful and free of personal data.

The Option B and C cards are preliminary and are included to show their common testing logic, not as completed implementation packs.

## Printing and distribution

- **Test-Decide-Confirm Card:** one copy per prototype / creator group; it is the canonical CORE 3 student record.
- **CORE 2 → CORE 3 Handover Card:** one completed copy per creator group, given to the testing group during the exchange.
- **Scratch student card:** one copy per Scratch group or project it for the class.
- **Completed examples:** use for modelling and differentiation, not as mandatory topics.
- **Option B/C preliminary cards:** distribute only for a teacher-prepared local pilot or partner review.

## Student outputs

Each group produces or demonstrates:

1. two mandatory independent peer tests;
2. input and observed-behaviour evidence;
3. one verified strength and one key finding;
4. one short comparison with the CORE 2 mini-test baseline;
5. one evidence-based **Improve** or **Keep as designed** decision;
6. one matched verification test;
7. final CORE 1 principle validation; and
8. one concise reflection naming a strength, a remaining limitation and one reason human judgement is still needed.

## Classroom feasibility

The 45-minute implementation is realistic when pairings are prepared in advance, prototypes are open and test-ready, Scratch groups exchange seats rather than files, only two tests are mandatory, only one focused change is permitted, and the final reflection remains concise. If a digital prototype fails to open, use the paper logic as the testable fallback instead of spending the lesson rebuilding it.

## Core message

Students do not need to rebuild or expand the chatbot. They need to test it independently, record evidence, make a justified creator decision, verify that decision and communicate one honest remaining limitation.
